# План ядра RC2014 для Karabas Go / Mini / Mini G

Цель: модульный Z80-компьютер [RC2014](https://rc2014.co.uk/) с периферией, которая под него выпускается, на платах Karabas (XC6SLX25, ISE 14.7). Своё ядро: на шине RC2014 стоят обычные микросхемы, их модели у нас уже есть. Ядра RC2014 для MiSTer / MiST на 2026-11-18 не нашлось, есть только FPGA-платы для шины (TMS9918 + AY на Tang Nano, V9958).

## Решения пользователя (2026-11-18)

- Процессор Z80 (T80). Z180 и eZ80 потом, в беклоге.
- Три профиля в OSD: **RomWBW 512K** (основной), **Classic** (SCM + NASCOM BASIC, CP/M с CF), **Mini / Micro** (BASIC 32K на ACIA).
- Консоль по умолчанию — встроенный в FPGA терминал VT100 на SIO A / ACIA, вывод на HDMI, клавиатура USB в терминал. TMS9918 — в Ф3.
- ROM (SCM, BASIC, RomWBW) встроены в `.kg`.
- Имя ядра `rc2014`, репозиторий karabas-go-core-rc2014, публичный.

## Блоки и откуда они

| Модуль RC2014 | У нас |
|---|---|
| Z80 7,3728 МГц | T80 |
| Pageable ROM, 64K RAM, 512K ROM + 512K RAM (банки) | SRAM платы 4 МБ |
| Serial I/O (ACIA 68B50), Dual Serial (SIO/2) | свои блоки |
| Compact Flash (8-битный IDE) | `hdf_ata.v` + `img_sdc` из modules (образ на SD1 через прошивку) |
| RTC DS1302 | свой блок, время от прошивки (`kg_mcu_rtc`) |
| Z80 CTC | свой блок (таймер и прерывания для Fuzix / RomWBW) |
| TMS9918A (J.B. Langston) | `vdp18` из core-msx |
| YM2149 (Ed Brindley) | `jt49` из core-msx |
| Джойстики | геймпады USB через прошивку |
| Терминал (Pi Zero / Pico VGA) | терминал VT100 из [tsybulin/karabas-go-core-pdp2026](https://github.com/tsybulin/karabas-go-core-pdp2026) 0f5a071 (pdp2011 vt10x, Sytse van Slooten, некоммерческая лицензия; у tsybulin клавиатура скан-кодами через FIFO `afifo.v` (Gisselquist, GPL-3), окно 640 пикселей, цвета amber / green / white) — решение пользователя 2026-11-18 вместо копии из core-vt100 |
| Второй последовательный порт | SIO B → `kg_mcu_uart` (мост через MCU), XMODEM с ПК |

Эталон для проверки — эмулятор Alan Cox [EmulatorKit](https://github.com/etchedpixels/emulatorkit) `rc2014`: 512K, ACIA, SIO/2, CTC, CF, DS1302, TMS9918A (без спрайтов). Трассы загрузки и снимки экрана сверяем с ним.

Софт: SCM (Steve Cousins), NASCOM BASIC (Grant Searle / Spencer Owen), RomWBW 3.6 (`RCZ80_std`: нужен модуль 512K, ACIA и SIO определяет сам), CP/M 2.2 / CP/M 3 / ZSDOS / Fuzix на CF, загрузчик MSX8 (игры MSX на TMS + AY).

## Плата

XC6SLX25: 15 032 LUT6, 30 064 FF, 52 RAMB16. SRAM 4 МБ, SDRAM 32 МБ. Вход 50 МГц. Z80 7,3728 МГц (ACIA: 7,3728 / 64 = 115 200 бод), турбо 14,7456 МГц — пункт OSD.

Прогоны 2026-11-18: **mini** — «Z80 BASIC Ver 4.7b … 32382 Bytes free», `PRINT 2+2` = 4; **classic** — SCM 1.0.0 на SIO/2, справка `?`; **romwbw_rom** — HBIOS 3.6.0 (Z2 MMU, 512K / 512K, ACIA, DS1302), загрузчик, `c` → CP/M 2.2, `dir b:` (ROM-диск); **romwbw_cf** — CF «ATA 8-BIT LBA 504MB» (образ `hd1k_combo.img`), загрузка с юнита 2, CP/M 2.2, `dir` A:.

  - RomWBW на SIO/2 в эмуляторе при вводе печатает «+++ BAD INT» (эмулятор держит прерывание SIO до RETI в IM1): эталоны RomWBW сняты на ACIA, SIO проверим своей симуляцией.
  - Эмулятор идёт в реальном времени и теряет символы, если слать их быстро: ввод по 0,3 с на символ.
- [x] XST на xc6slx25 (`make measure-all`, `make measure-vt`): цифры ниже.

Оценка ядра Mini G: 7,3k + ACIA / SIO/2 / CTC / DS1302 / 8242 (~1,0k, пишем сами) + обвязка платы (`kg_mcu2`, OSD, HDMI, звук, ~2,5k) ≈ **10,8k LUT (72 %)**, ~24 RAMB16. Влезает с запасом. Z80 на 7,37 / 14,74 МГц, терминалу нужно 10 МГц (PDP-11) и 50 МГц (развёртка) — частоты XST подходят.

Терминал — почти половина логики. Если в Ф1 понадобится место или своя развёртка 720×576, то запасной вариант — свой текстовый терминал VT100 (~1k LUT); пока берём готовый vt10x.

Ещё к Ф2: `hdf_ata` — 16-битная шина IDE; RomWBW работает с CF в 8-битном режиме (SET FEATURES 01h), `hdf_ata` эту команду принимает без действия — нужен 8-битный режим данных (обёртка или параметр модуля).

### Ф1 — Mini G, первый запуск (ветка f1-minig)

Верх платы на kg_* (`kg_mcu2`: OSD, клавиатура, загрузка ROM из `.kg` в SRAM), Z80, банки ROM / RAM трёх профилей, ACIA + SIO/2, терминал VT100 на HDMI (синхросигналы всегда есть), клавиатура USB → терминал → RX последовательного порта. Симуляция загрузки (Verilator / ghdl) против эталона из Ф0.
Цель: приглашение SCM, `Ok` у BASIC, загрузчик RomWBW и CP/M с ROM-диска.

Сделано (ветка f1-minig):
- `rtl/karabas/rc2014_machine.v`: T80s, такты Z80 7,3728 / 14,7456 МГц и последовательный такт 7,3728 МГц — фазовые аккумуляторы на 50 МГц; карты памяти профилей (RomWBW: Z2 78-7C; Classic: pageable ROM 38, ROM 16K = банк 2 образа 24886009; Mini: ROM 8K + RAM 32K); порт 00 читается 00, пустые порты FF.
- `rc2014_acia.v` (MC68B50 80-81), `rc2014_sio.v` (SIO/2 80-83, WR0-WR5, RR0-RR2, FIFO 3, прерывания IM1, вектор IM2 без daisy chain), `rc2014_ser.v` (линия 8N1).
- `rc2014_mem.v` (SRAM, загрузчик ROM), `rc2014_clocks.v` (один PLL: 50 / 25 / 125 / 10 / 8,3 МГц), `karabas_minig_top.v`.
- Терминал tsybulin: 640×480 60 Гц (его развёртка, пиксель 25 МГц), монохромный, цвет из OSD; звонок терминала → PCM5102 и HDMI.
- ROM: `tools/rc2014_roms.sh` → `roms/kg/{romwbw,classic,mini}.rom`.
- Симуляция `sim/run_machine.sh` (Verilator, T80s через `ghdl --synth`, `sim/sim_machine.cpp`: SRAM, линия 115200 в обе стороны, `--key`): **mini** — «Z80 BASIC Ver 4.7b … 32382 Bytes free», `PRINT 2+2` = 4 (как эталон); **classic** на SIO/2 — SCM 1.0.0, `?` выводит справку (как эталон; SCM сначала ~190 мс гоняет огни на порту 00); **RomWBW** на SIO/2 (IM1, прерывания SIO) — HBIOS 3.6.0, «Z80 @ 7.372MHz … Z2 MMU, 512KB ROM, 512KB RAM», SIO0 / SIO1 115200, загрузчик, `c` → «CP/M-80 v2.2, 54.0K TPA» за 4,5 с модели (~3 мин), без «BAD INT» эмулятора; DSRTC пока NOT PRESENT (Ф2). Скорость модели ~20 мс модельного времени в секунду.

На плате (Mini G, 2026-11-18/19), сборки 26111870-26111877:
- 26111870: RomWBW на SIO/2 → CP/M с ROM-диска сразу; Classic и Mini — печатный «мусор» в баннерах.
- Причина: в `kl11.vhd` терминала pdp2026 делитель выборки на 1 длиннее (`cdc <= clkdiv-1`: 115200 → 111607 бод), приёмник терял кадр на символах вплотную; исправлено (`karabas:`), автор pdp2026 извещён пользователем. Включён silo приёмника (`rtscts => 1`), RTS `kl11` выведен из `vt.vhd` (был не подключён).
- ACIA: статус 00 во время master reset (RomWBW так находит 6850).
- Турбо 14,75 МГц падал: T80 защёлкивает данные чтения в T2, через такт Z80 после MREQ, а /OE SRAM открывался по MREQ — теперь /OE открыт всегда, кроме записи (`rc2014_mem.v`).
- На турбо при прокрутке терялись символы: прошивка терминала шлёт XOFF (счётчик в DEBUG_DATA: 8 за три справки SCM), SCM / BASIC его не знают → `rc2014_xonxoff.v` держит передатчики линии терминала по XOFF / RTS и вынимает XON / XOFF из линии к машине (^S / ^Q с клавиатуры тоже ставят вывод на паузу).
- 26111877: Classic SCM `?` ×3 с прокруткой на 14,75 МГц чисто; RomWBW SIO/2 и ACIA → CP/M, `dir b:`; Mini BASIC (32382 Bytes free, FOR, PRINT); цвета Amber / Green; OSD (кадр показан пользователю).

| Сборка | LUT | Slices | RAMB16 | Время |
|---|---|---|---|---|
| 26111877 Mini G | 7 354 (48 %) | 2 671 (71 %) | 13 | всё сходится |

### Ф2 — накопители и время (ветка f2-storage)

CF на образе SD1 (чтение и запись), DS1302, CTC с прерываниями (режим 2 / IM1 как в RomWBW), SIO B через MCU.
Цель: CP/M 2.2, CP/M 3 и ZSDOS с CF; `TIME` / `RTC`; загрузка Fuzix; передача файла XMODEM.

Сделано (ветка f2-storage, 2026-11-19):
- `rc2014_cf.v`: порты 10-17, `hdf_ata` из modules на образе файлового монтировщика (слот 4 = устройство 0), регистр данных всегда 8-битный (младший, затем старший байт), как 8-битная шина модуля CF.
- `rc2014_ds1302.v`: порт C0 (`DSRTCMODE_STD`: D7 данные, D6 SCLK, D5 RD, D4 CE; чтение D0), регистры DS1307 часов платы в RTC `kg_mcu2` (`rtc_mode` 1, `ENABLE_RTC`); запись времени уходит в прошивку, RAM DS1302 = RAM DS1307 08-26.
- OSD: CF card (слот 4, Menu+F1, `.img` / `.hdf`, `/rc2014`).
- Образ CF для проверки: `hd1k_prefix.dat` + `hd1k_cpm22.img` + `hd1k_cpm3.img` RomWBW 3.6 (17 МБ).
- Симуляция (`--cf`, модель монтировщика и RTC с ходом секунд — RomWBW меряет частоту по секундам DS1302): DSRTC время, «Z80 @ 7.376MHz», IDE0 ATA 8-BIT 17MB, загрузка CP/M 2.2 с CF, `dir`.
- OSD с пунктом CF card одобрен пользователем (2026-11-19).
- Плата 26111901 (8 800 LUT 58 %, 81 % slices): IDE0 17MB, загрузка CP/M 2.2 с CF, `PIP` запись на CF и обратно, RTC.COM — время часов платы (дата на плате сбита, это не ядро).

Сделано 26111902: настоящая CF-карта (OSD «CF source»: Image / Card, смена = сброс машины; OSD одобрен пользователем 2026-11-19) — на плате карта 978 МБ «CompactFlash» определяется (IDENTIFY, 8-битный режим) на 7,37 и 14,75 МГц, только чтение (на карте данные пользователя: не писать); Image после этого работает как прежде.

Ф2 закрыта на этом (пользователь 2026-11-19): CTC, SIO B через MCU и Fuzix — в беклог. Без них работает всё, что есть (CP/M, BASIC, SCM, CF, часы); таймер для Fuzix можно взять и от кадрового прерывания TMS9918 (Ф3).

### Ф3 — графика, звук, джойстики (ветка f3-tms)

TMS9918A (вывод на HDMI вместо терминала по пункту OSD), YM2149 в микшер, джойстики, консоль RomWBW на TMS + клавиатура.
Цель: CP/M-игры под TMS, игры MSX через MSX8, звук AY.

Решения пользователя (2026-11-19): второй порт — сразу на выделенный CDC прошивки (fw #157: CDC 1 «Karabas core serial» = чистый UART ядра, порт 0 `kg_mcu2`); на плате в Ф3 не проверяем, фаза заканчивается сборкой под все платы.

Сделано (ветка f3-tms, сборка 26111903):
- SIO/2 канал B — байтовый поток порта 0 `kg_mcu2` (`ENABLE_PORTS(4'b0001)`, как в core-term): байт с USB входит в FIFO канала, только когда FIFO пуст и приём включён (остальное ждёт в MCU, без переполнения); байт передатчика уходит сразу, если в MCU есть место. RomWBW видит его как SIO1 (XM, вторая консоль).
- TMS9918A (`vdp18` из core-msx, VRAM 16K в BRAM) на 98 / 99, кадровое прерывание на INT (IM1); картинка через кадровый буфер `msx_video` (из core-msx ffde047, 256 × 192 → 512 × 384 в 640 × 480 @ 60 Гц, та же развёртка, что у терминала).
- YM2149 (`jt49`) на D8 / D0 (модуль Ed Brindley: D8 запись — номер регистра, чтение — данные; D0 запись — данные), 3,579545 МГц / 2 = 1,79 МГц (AY_CLK RomWBW); в звук вместе со звонком терминала.
- Джойстики: геймпады MCU на портах 01 / 02 (модуль Joystick, активный 0: 0 вверх, 1 вниз, 2 влево, 3 вправо, 4 огонь 1, 5 огонь 2) и на порту A YM2149 (как MSX, выбор бит 6 порта B — для MSX8). Раскладку битов модуля 01 / 02 проверить по софту.
- 8242 (`rc2014_kbd8242.v`) на 60 / 64 для `TMSMODE_MSXKBD`: самотест, команды 20 / 60, ответы клавиатуры (FF → FA AA, ED / F3 / F0 + параметр, F2, EE), FIFO 16 байт; клавиатура — PS/2 set 2 от `kg_mcu2`.
- OSD: Console (Terminal / TMS9918, Menu+C, index 6): TMS — на HDMI картинка TMS, клавиатура в 8242, порт 00 читается 80 (SW_CRT: RomWBW переносит консоль на TMS при загрузке); смена — сброс машины. **Вид OSD показать пользователю.**
- Свой RomWBW: `roms/romwbw/RCZ80_kg.asm` (RCZ80_std + TMSENABLE, TMSMODE_MSXKBD, TMSTIMENABLE, AY38910ENABLE), `tools/rc2014_romwbw.sh <work dir>` собирает его из исходников 3.6.0. Для сборки нужны пакеты `srecord` и `libncurses-dev` (поставлены пользователем 2026-11-19); `romwbw.rom` в `.kg` теперь наш RCZ80_kg (сборка RomWBW: «TMS: MODE=MSXKBD, IO=152, SCREEN=40X24, KEYBOARD=KBD, INTERRUPTS ENABLED», «AY38910: MODE=RC2014, IO=216, CLOCK=1789772 HZ», «SYSTEM TIMER: TMS»). ROM лежит только в `.kg`: после сборки ROM — `make_core` без новой прошивки ПЛИС. zxcc под Linux прерывает LINK, если stdin не терминал: скрипт подставляет пустой FIFO.
- Симуляция `sim/run_f3.sh` (тест `sim/tests/f3_test.asm`, uz80as из инструментов RomWBW): VRAM, регистр YM2149, джойстики (порт A, 01, 02), 8242 (самотест 55, скан-коды), 15 кадровых прерываний за 0,25 с, эхо канала B, снимок экрана TMS «HELLO RC2014» — всё сходится.
- Сборка 26111903 всех плат (`rc2014.kg`: go, mini, minig), тайминги сходятся везде:

| Плата | LUT | Slices | RAMB16 |
|---|---|---|---|
| Mini G | 10 006 (66 %) | 3 282 (87 %) | 33 |
| Mini | 10 155 (67 %) | 3 332 (88 %) | 33 |
| Go | 9 226 (61 %) | 3 239 (86 %) | 33 |

- Плата Mini G, 26111903 (2026-11-19): загрузчик RomWBW видит SIO1, TMS0 (Text 40x24), SND0 AY-3-8910; SIO1 = CDC 1 (`-if02`) в обе стороны (`I 1` в загрузчике, ROM BASIC на нём); AY на HDMI: тон 788 Гц (расчёт 1789772 / 16 / 142 = 787,7); Console = TMS9918: «FP Switches = 0x80», загрузчик и ROM BASIC на экране TMS, клавиатура через 8242 (с Shift). Первая сборка ROM была без шрифта 6×8 (пустой `font6x8u.asm` от прогона без `bin2asm`): скрипт теперь собирает с чистого дерева и проверяет шрифт. Go и Mini на плате не были. Кадр OSD с Console показан пользователю.

## OSD (набросок, показать пользователю до мержа Ф1)

Ф1 (core.json, одобрено пользователем 2026-11-19): Profile (RomWBW 512K / Classic / Mini), Serial (SIO/2 / ACIA; Mini всегда ACIA), CPU (7.37 / 14.75 MHz), Colour (Amber / Green / White, как у pdp2026), Reset (Menu+F12). Потом: Console (Terminal / TMS9918, Ф3), CF image (Ф2).

## Беклог

Z80 CTC на 88-8B (IM2-векторы, каскад 2→3, своя сборка RomWBW `CTCENABLE` / INTMODE 2) — таймер для Fuzix; SIO B через MCU (`kg_mcu_uart`, XMODEM с ПК); Fuzix на CF (таймер от CTC или кадрового прерывания TMS9918). V9958 (из core-msx2), SN76489, WD37C65 + образы дискет, Wi-Fi через ESP, модули Z180 и eZ80 (eZ80 из core-agon), принтер.
